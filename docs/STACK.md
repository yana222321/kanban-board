# Выбор технологического стека

Документ фиксирует обоснование выбора технологий и оценку альтернатив для каждой категории.

## 1. Язык программирования

| Вариант        | Плюсы                                            | Минусы                                       |
| -------------- | ------------------------------------------------ | -------------------------------------------- |
| **TypeScript** | Статическая типизация, единый язык на FE и BE, поддержка в IDE, безопасный рефакторинг | Этап компиляции, порог входа |
| JavaScript     | Быстрый старт                                    | Ошибки типов в рантайме, слабая поддержка рефакторинга |
| Python         | Простой синтаксис                                | Разный язык на FE/BE, слабая типизация FE    |

**Выбрано: TypeScript** — единый типизированный язык для frontend и backend снижает число ошибок и упрощает сопровождение.

## 2. База данных

| Вариант          | Тип           | Плюсы                                             | Минусы                          |
| ---------------- | ------------- | ------------------------------------------------- | ------------------------------- |
| **PostgreSQL**   | Реляционная   | ACID, богатые типы, JSONB, транзакции, бесплатна  | Требует отдельного сервера      |
| MySQL/MariaDB    | Реляционная   | Распространённость                                | Меньше возможностей (CTE, JSON) |
| MongoDB          | Документная   | Гибкая схема                                      | Сложнее поддержать целостность связей |
| SQLite           | Встроенная    | Простая                                           | Не подходит для многопользовательской нагрузки |

**Выбрано: PostgreSQL** — реляционная модель (пользователи, проекты, доски, карточки) с чёткими связями и ограничениями целостности, поддержка конкурентного доступа и транзакций для WIP-проверок.

## 3. Backend-фреймворк

| Вариант          | Плюсы                                    | Минусы                         |
| ---------------- | ---------------------------------------- | ------------------------------ |
| **Express 5**    | Минимализм, огромная экосистема, гибкость | Много ручной настройки         |
| NestJS           | Готовая архитектура, DI, декораторы       | Тяжелее, выше порог входа      |
| Fastify          | Высокая производительность                | Меньше примеров и плагинов     |

**Выбрано: Express 5** — прозрачность, гибкость и достаточная производительность для учебного проекта; архитектура разделена на слои вручную (routes → controller → service).

## 4. ORM / доступ к данным

| Вариант            | Плюсы                                    | Минусы                        |
| ------------------ | ---------------------------------------- | ----------------------------- |
| **Prisma**         | Типобезопасный клиент, миграции, интроспекция, DX | Тяжёлый движок, генерация     |
| TypeORM            | Декораторы, паттерн Active Record/Data Mapper | Сложнее типизация, нестабильные мажоры |
| Knex (query builder) | Полный контроль над SQL                | Ручная типизация и миграции   |
| raw SQL            | Максимальная производительность          | Много шаблонного кода, ошибки  |

**Выбрано: Prisma** — сгенерированный типобезопасный клиент напрямую повышает надёжность кода и ускоряет разработку; декларативная схема и миграции упрощают воспроизводимость БД.

## 5. Frontend

| Категория   | Выбрано              | Альтернатива        | Обоснование                                         |
| ----------- | -------------------- | ------------------- | --------------------------------------------------- |
| Библиотека  | **React 18**         | Vue, Angular, Svelte | Широкая экосистема, компонентный подход, поддержка |
| Сборщик     | **Vite**             | Webpack, CRA        | Быстрый dev-сервер (HMR), простая конфигурация      |
| UI-kit      | **MUI 5**            | Ant Design, Chakra  | Готовые компоненты, темизация, доступность          |
| Состояние   | **Redux Toolkit**    | Zustand, Context    | Предсказуемость, devtools, единый store             |
| Drag & drop | **dnd-kit**          | react-beautiful-dnd | Активная поддержка, доступность, лёгкость           |

## 6. Аутентификация

JWT (access + refresh) с хешированием паролей bcrypt. Access-токен короткоживущий (1 ч), refresh — длительный (7 дней). Альтернатива — серверные сессии (cookie): проще в отзыве, но хуже масштабируется и требует состояния на сервере.

## 7. Тестирование

| Уровень         | Инструмент          | Обоснование                                        |
| --------------- | ------------------- | -------------------------------------------------- |
| Модульное       | Jest                | Де-факто стандарт для JS/TS, быстрый, снапшоты      |
| Интеграционное  | Jest + Supertest    | Тестирование HTTP API без реального сервера         |
| E2E             | Playwright          | Кроссбраузерность, авто-ожидания, трейсы/видео      |
| Нагрузочное     | k6                  | Сценарии на JS, метрики и пороги                    |
| Security        | npm audit, OWASP ZAP | SCA зависимостей + динамический DAST-скан           |

## 8. CI/CD и развёртывание

- **GitHub Actions** — бесплатно для публичных репозиториев, матричная сборка, сервис-контейнеры (PostgreSQL).
- **Docker / docker-compose** — воспроизводимое окружение, единый запуск БД, backend и frontend.

## Итог

Стек «TypeScript + PostgreSQL + Express + Prisma + React + Vite» оптимален для учебного проекта: единый типизированный язык, типобезопасная работа с БД, современный DX и полный набор инструментов для тестирования и CI/CD.
